# 데이터, 점수, 리스크 원칙

## 결과를 읽는 법

점수는 **현재 규칙에 맞는 후보를 동일한 방식으로 정렬하는 도구**입니다. 원천 데이터, 원천에서 계산한 지표, 지표를 점수로 바꾼 규칙, 그리고 사람이 내리는 해석을 구분해야 합니다.

| 구분 | 예 | 화면/저장 시 필요한 정보 |
|---|---|---|
| 원천 사실 | 종가, 희석 EPS, 공시 매출 | source, 조회 시각, 기간 말일, 통화·단위 |
| 계산 지표 | 고점 대비 하락률, PER 괴리, 200일 이격도 | 산식, 가격 조정 기준, 사용 관측치 수 |
| 규칙 결과 | `-30% 이하 → +3점` | 규칙 버전, 구간 경계, 결측 처리 |
| 해석 | 저평가 후보, 추가 확인 필요 | 근거와 반대 위험, 확신 수준 |

총점이 높다는 사실만으로 기업 가치가 싸거나 주가 반등 확률이 높다고 단정하지 않습니다.

## 현재 점수 규칙 v2.0.0

실행 코드와 `/api/rules`가 최종 기준입니다. 현재 회사 점수 구간은 다음과 같으며, 어느 구간에도 해당하지 않으면 0점입니다.

| 지표 | 조건과 점수 |
|---|---|
| 52주 고점 대비 하락률 | `≤ -30%: +3`, `≤ -15%: +2`, `≤ -5%: +1` |
| 3년 Forward PER 괴리 | `≤ -20%: +2`, `≤ -10%: +1` |
| 200거래일 이동평균 이격도 | `≤ -20%: +2`, `≤ -5%: +1` |
| 최근 연간 희석 EPS 성장률 | `≥ 20%: +2`, `≥ 5%: +1`, `≤ -20%: -2`, `≤ -5%: -1` |
| Wilder RSI(14) | `≥ 75: -2`, `≥ 65: -1`, `≤ 25: +1` |
| 3년 평균 주주환원율 프록시 | `≥ 6%: +3`, `≥ 4%: +2`, `≥ 2%: +1` |
| 최근 3년 희석주식수 증감 | `≥ 10%: -3`, `≥ 5%: -2`, `≥ 1%: -1` |
| 부채/자기자본 | `≥ 4.0: -2`, `≥ 2.0: -1`, `≤ 0.25: +1`; 금융사·REIT 제외 |
| 3년 현금흐름 품질 | `≥ 1.2: +2`, `≥ 0.9: +1`, `≤ 0.75: -1`, `≤ 0.5: -2`; 금융·부동산·REIT 제외 |

시장 보조 점수는 SPY 52주 하락률(`≤ -20%: +1`, `> -5%: -1`), VIX(`≥ 30: +1`, `≤ 12: -1`), 선택적 CNN Fear & Greed(`≤ 25: +1`, `≥ 75: -1`)로 구성합니다. 공급자가 실패한 선택 지표는 0점으로 가장하지 않고 `N/A`로 둡니다.

현재 회사 점수는 위 9개 규칙만 합산합니다. 섹터 내 상대가치와 S&P 500 상대 모멘텀은 규칙 및 대시보드 표시 factor가 아닙니다. 시가총액은 공급자·모델 내부 입력으로 남을 수 있지만 score/display factor가 아니며, 점수·화면 신호로 해석하지 않습니다. 회사 지표 중 최소 5개가 유효해야 순위 대상이 됩니다. 총점 기준 추천 단계는 `10점 이상: 강력 매수`, `5~9점: 매수 관심`, `-2~4점: 중립`, `-7~-3점: 매도 관심`, `-8점 이하: 매도`이며 유효 지표가 부족하면 점수와 관계없이 `데이터 부족`입니다.

## 데이터 우선순위

1. 재무제표와 기업 사건을 검증할 때는 SEC EDGAR의 10-K, 10-Q, 8-K 및 기업 IR을 우선합니다. 현재 기본 구현은 이 공식 계층을 자동 수집하지 않습니다.
2. S&P 500 유니버스는 현재 구성 종목과 조회일을 함께 저장합니다.
3. 가격·배당·분할은 거래소 또는 계약된 공급자를 우선하고, 무료 공급자·Yahoo Finance·Stooq 등은 편의 계층임을 표시합니다.
4. 공급자 계산 비율은 정의가 불투명할 수 있으므로 가능한 경우 원천 수치로 재계산하고 계산값임을 표시합니다.

현재 기본 공급자는 Yahoo Finance/yfinance입니다. 주가는 `auto_adjust=False, actions=True`로 받은 2년 일별 `Adj Close`와 `Stock Splits` 이벤트를 사용합니다. 새 분할 직후 Yahoo가 과거 `Adj Close`를 아직 소급 조정하지 않아 분할일에 가짜 급락이 생길 수 있으므로, 공급자가 공시한 분할 이벤트 전후의 여러 가격 표본이 연속값보다 분할 배수에 명확히 가까울 때만 분할 이전 `Adj Close`를 조건부 보정합니다. 이미 연속 조정된 이력은 다시 나누지 않으며, 종목별 예외값을 하드코딩하지 않습니다. 이 보정은 공급자 지연을 완화할 뿐 거래소 공식 가격을 대체하지 않습니다. 펀더멘털은 Yahoo quote summary와 연간 손익계산서·현금흐름표에 의존합니다. 이는 비공식 편의 계층이며 재배포 계약, 필드 정의, 조정 방식과 endpoint가 바뀔 수 있습니다. 상세 그래프의 약 5년 주간 Forward/Trailing PER은 StockAnalysis의 분기별 `Last Close Price`, `PE Ratio`, `Forward PE`에서 이익 분모를 역산하고 Yahoo `Close(auto_adjust=False)`의 매주 마지막 거래일 가격으로 재계산합니다. StockAnalysis가 표시하는 기초 공급자는 회사별로 다를 수 있으며, `Last Close Price`가 없는 종목은 해당 분기 말 이전의 가장 가까운 Yahoo 종가를 사용합니다. 공급자 연결이 실패할 때만 날짜 없는 기존 로컬 스냅샷을 `T-5~T-1` 폴백으로 사용합니다.

### 포트폴리오 시각화 데이터 경계

- 미국 검색은 Yahoo 검색 결과 중 미국 거래소의 `EQUITY`와 `ETF`만 사용하며 S&P 500 구성 종목으로 제한하지 않습니다. 현재가와 USD/KRW도 Yahoo chart 편의 endpoint이므로 지연·장중 변동·통화 표기 오류가 있을 수 있습니다.
- KOSPI 검색 목록은 KRX 업무일을 확인한 뒤 FinanceDataReader의 `fdr_krx_data_cache` GitHub 미러에서 `STK/KOSPI` 행만 선택합니다. 이는 공식 KRX Open API 응답이 아니라 제3자 미러입니다. 실제 시세 조회 티커는 6자리 코드에 `.KS`를 붙입니다.
- 금은 `M04020000` 국내 금 표시값을 네이버 모바일 market-index에서 읽고 원/g로 사용합니다. 공식 KRX API가 아니며, 수량 단위만 KRX 금시장의 1g 거래 단위에 맞춥니다.
- 평가액은 `수량 × 현지 가격 × 적용 환율`에 사용자가 직접 입력한 원화 현금을 더한 단순 현재가 스냅샷입니다. 입력 현금은 계좌 조회값이 아니며 평균 매입단가, 평가손익, 배당, 세금, 수수료, 환전 스프레드, 주문 가능 금액과 실제 계좌 잔고는 포함하지 않습니다.
- 일부 시세가 없으면 그 자산을 합계에서 제외하고 화면에 명시합니다. 이 경우 보이는 비중은 가격을 받은 자산끼리의 비중이지 전체 실제 자산의 비중이 아닙니다.

SEC를 반복 호출할 때는 연락 가능한 설명형 `SEC_USER_AGENT`를 설정하고 공급자 이용약관과 호출 제한을 지킵니다. 전체 종목 수집은 개별 endpoint를 과도하게 두드리기보다 bulk 자료와 캐시를 우선합니다.

## 핵심 지표 정의

엔진의 버전된 규칙이 최종 기준이며, 아래는 의미와 방어적 계산 원칙입니다.

### 고점 대비 하락률

```text
drawdown = current_adjusted_close / window_high_adjusted_close - 1
```

창은 명시적으로 정합니다(예: 52주 또는 전체 관측 구간). 장기간 비교에는 배당·분할 처리가 일관된 조정종가를 사용합니다. 큰 하락은 기계적 가격 매력 점수를 높일 수 있지만 파산, 규제, 희석, 사업 훼손을 반영한 정상적 재평가일 수도 있습니다.

요청된 핵심 구간 예시는 `-30% 이하 → +3점`입니다. 더 작은 하락 구간과 반대 방향 감점은 코드에 버전된 규칙으로 명시하고 `/api/rules`에서도 같은 내용을 반환해야 합니다.

### 3년 PER 괴리

```text
pe_gap_3y = current_pe / valid_3y_reference_pe - 1
```

3년 기준 PER이 평균인지 중앙값인지, 일별·월별 관측인지 규칙 버전에 고정합니다. 왜곡을 줄이려면 유효한 양(+)의 EPS/PER만 사용하고 극단값 처리 방식을 기록합니다. 현재 또는 기준 PER이 유효하지 않으면 `N/A`로 두며, 값이 싸 보이도록 음수 PER을 점수화하지 않습니다.

상세 화면의 5년 비교 그래프와 점수 창은 구분합니다. 그래프는 StockAnalysis 분기 비율에서 역산한 최신 분기 EPS 분모를 다음 앵커까지 유지하고, Yahoo의 매주 마지막 종가로 약 240~260개의 주간 Forward/Trailing PER을 계산합니다. 이는 매주 관측한 애널리스트 컨센서스가 아니라 가격 민감도 프록시이며, 분기 말일과 실제 정보 공개일의 차이 때문에 시점 보존형 백테스트에는 적합하지 않습니다. `3Y Forward PER 괴리` 점수는 이 주간 프록시로 바꾸지 않고 가장 최근 비교 가능한 기존 Forward PER 스냅샷 3개만 중앙값에 사용합니다.

요청된 기본 구간 예시는 `-20% 이하 → +2점`, `-10% 이하 → +1점`입니다. 정확한 경계 포함 여부와 나머지 구간 점수는 `/api/rules`가 제공하는 엔진 규칙을 따릅니다.

### 200거래일 이동평균 이격도

```text
ma200_distance = current_adjusted_close / mean(last_200_adjusted_closes) - 1
```

달력 200일이 아니라 거래일 200개가 필요합니다. 신규 상장, 거래정지, 데이터 누락으로 관측치가 부족하면 완전한 200일 지표처럼 표시하지 않습니다. 큰 음의 이격은 과매도 후보인 동시에 강한 하락 추세 신호일 수 있습니다.

### 최근 1년 EPS 성장률

```text
eps_growth_yoy = latest_comparable_eps / prior_year_comparable_eps - 1
```

연간 기준이면 최근 회계연도와 직전 회계연도, TTM 기준이면 동일한 TTM 방식끼리 비교합니다. 분모가 0에 가깝거나 부호가 바뀌면 단순 성장률이 폭발하거나 의미가 뒤집히므로 `N/A` 또는 별도 전환 상태로 처리합니다. 일회성 손익, 주식 수 변화, GAAP/non-GAAP 혼용 여부도 확인합니다.

### 3년 현금흐름 품질

```text
cash_flow_quality_3y =
  sum(operating_cash_flow over 3 fiscal years)
  / sum(net_income over the same 3 fiscal years)
```

회계연도 말일이 일치하는 최근 3개 기간만 사용합니다. 누적 순이익이 0 이하이거나 비교 기간이 부족하면 비율의 의미가 불안정하므로 `N/A`입니다. 일반 기업에서 이익이 실제 영업현금으로 전환되는 정도를 보는 보조 지표이며, 운전자본 변동과 일회성 현금 유입 때문에 단일 기간 비율은 크게 흔들릴 수 있어 누적값을 사용합니다. 금융·부동산·REIT에는 이 단순 기준을 적용하지 않습니다.

### 3년 주주환원 프록시와 주식수 희석

```text
average_net_share_reduction = mean((prior_diluted_shares - current_diluted_shares) / prior_diluted_shares)
shareholder_return_proxy = average_dividend_yield + max(average_net_share_reduction, 0)
shares_change_3y = latest_diluted_shares / oldest_diluted_shares - 1
```

배당수익률 3개와 약 1년 간격의 연간 희석가중평균주식수 4개가 모두 있어야 계산합니다. 이 값은 공급자가 보고한 현금 주주환원율이 아니라 **계산 프록시**입니다. 희석주식수 감소는 자사주 매입 효과를 간접적으로 보여 주지만 현금 매입액, 평균 매입 가격, 주식기준보상(SBC), 전환증권과 신규 발행을 각각 분해하지 못합니다.

배당수익률은 검증된 legacy 배열의 최근 3개 슬롯을 사용하며 정확한 회계연도 날짜가 없으므로 결과를 `stale`로 표시합니다. 희석이 발생한 음(-)의 순감소율은 주주환원 프록시에서 0으로 제한하고, 3년 누적 주식수 증가 규칙에서만 감점해 한 요인을 두 번 벌점 주지 않습니다. 주식수 감소도 희석 규칙에서 다시 가점하지 않습니다.

배당 이력이 누락됐다는 사실만으로 무배당 0%를 추정하지 않습니다. 검증된 배당수익률 3개가 없으면 주주환원 프록시는 `N/A`입니다. 인접한 비교 연도의 희석주식수가 10배 이상 불연속이면 주식분할 반영 또는 공급자 단위 오류 가능성이 있으므로 해당 3년 창 전체의 주식수 파생값과 차트를 보류합니다.

## 결측·오류 처리

- 없는 값을 0점이나 업종 평균으로 조용히 대체하지 않습니다. `null`/`N/A`와 사유를 표시합니다.
- 점수 계산에 포함된 유효 지표 수를 함께 보여 줍니다. 같은 총점이어도 대부분의 지표가 있는 종목과 일부만 있는 종목은 신뢰도가 다릅니다.
- 마지막 성공 캐시를 쓸 때는 `stale=true`, 원래 기준일, 갱신 실패를 보존합니다.
- 공급자 두 곳의 값이 다르면 최신 값을 임의 선택하지 말고 기간, 조정 방식, 통화, 희석/기본 EPS 정의부터 맞춥니다.
- 오류가 난 종목 때문에 전체 배치를 폐기하지 않되, 실패 종목 목록과 성공/실패 수를 갱신 보고서에 남깁니다.
- JSON에는 `NaN`이나 무한대를 내보내지 않고 계산 불능을 `null`로 변환합니다.

## S&P 500 유니버스 위험

- 지수 구성은 수시로 바뀌며 복수 주식 클래스 때문에 약 500개 기업과 실제 티커 수가 다를 수 있습니다.
- 오늘의 구성 종목만으로 과거 성과를 계산하면 퇴출·파산 기업이 빠지는 생존편향이 생깁니다.
- 과거 백테스트에는 각 날짜의 historical membership과 편입·편출 효력일이 필요합니다.
- 티커는 바뀌거나 재사용될 수 있습니다. 장기 이력은 가능하면 CIK와 발행사 식별자를 함께 보관합니다.

## 업종별 해석 차이

- 은행·보험: 일반 기업의 순부채/EBITDA보다 P/B, ROTCE, CET1, 충당금·준비금이 중요합니다.
- REIT: EPS와 PER보다 FFO/AFFO, NAV, 점유율, 부채 만기와 배당 커버리지를 봅니다.
- 유틸리티: 허용 ROE, 규제 자산, 금리 민감도와 부채가 핵심입니다.
- 에너지·소재: 상품 사이클 한 시점의 EPS/PER을 정상 이익으로 착각하기 쉽습니다.
- 고성장 소프트웨어: SBC 희석, 매출 유지율, FCF 마진을 함께 보지 않으면 EPS 성장만으로 품질을 오판할 수 있습니다.

따라서 전체 유니버스 점수만으로 업종 차이를 해석하지 말고 별도의 업종 분석을 수행해야 합니다.

## 백테스트와 모델 위험

- 모든 재무 수치는 공시일 이후에만 사용할 수 있도록 point-in-time으로 정렬해야 합니다. 회계 기간 말일에 이미 공개된 것으로 취급하면 look-ahead bias가 생깁니다.
- 주가 수익률은 분할, 배당, 상장폐지, 거래 비용, 슬리피지와 실제 재조정 시점을 포함해야 합니다.
- 구간과 가중치를 과거 결과에 반복 최적화하면 과최적화 위험이 큽니다. 학습/검증/최종 구간을 분리하고 규칙 버전을 고정합니다.
- 추천 단계별 표본 수, 최대 낙폭, 변동성, 업종 쏠림과 시장 국면별 성과를 총수익률과 함께 봅니다.
- 화면의 점수 변경은 모델 변경입니다. 규칙 버전, 적용 시각, 변경 이유를 남기지 않으면 결과를 재현할 수 없습니다.

## 운영과 라이선스 위험

- 무료 API는 호출량, 지연, 재배포, 상업 이용을 제한할 수 있습니다. 제품 배포 전에 각 데이터 계약을 다시 확인합니다.
- API 키와 사용자 식별 문자열을 브라우저 코드나 Git 저장소에 넣지 않습니다.
- 로컬 서버의 기본 바인드 `127.0.0.1`을 유지합니다. 외부 공개 시 인증, TLS, 요청 제한과 비밀 관리가 별도 필요합니다.
- `full` 갱신은 시간이 오래 걸리고 부분 실패할 수 있습니다. 마지막 성공 자료와 새 자료를 원자적으로 교체하거나 행 단위 상태를 기록해야 합니다.

## 투자 관련 고지

이 애플리케이션은 교육·연구와 후보 선별을 위한 도구입니다. 투자자문, 투자 권유, 적합성 판단, 목표가 또는 수익 보장이 아닙니다. 높은 점수에도 영구 손실이 발생할 수 있으며 데이터 오류·지연·결측과 모델 한계가 존재합니다. 실제 거래 전 최신 공시와 기업 자료를 검증하고 개인의 목적, 기간, 세금, 유동성, 손실 감내 수준을 독립적으로 고려해야 합니다.
